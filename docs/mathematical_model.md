# Μαθηματικό μοντέλο

## Κατάσταση και σειρά ανάπτυξης

Πρώτα υλοποιείται ντετερμινιστικό LP/MILP. Ακολουθεί επέκταση με σενάρια και CVaR μόνο αφού επαληθευτούν δεδομένα, χρονισμός και baseline. Η παρακάτω διατύπωση είναι σχεδιασμός, όχι ελεγμένος κώδικας ή πιστοποιημένος κανόνας αγοράς.

## Χρόνος και μεταβλητές

Κάθε t αντιστοιχεί σε περίοδο παράδοσης διάρκειας Δt ωρών.

| Σύμβολο | Έννοια | Μονάδα |
| --- | --- | --- |
| G_t | Παραγωγή ΑΠΕ πριν από προαιρετική περικοπή | MWh |
| C_t | Ελεγχόμενη περικοπή, μόνο αν επιτρέπεται | MWh |
| Q_DA,t | Καθαρή εκτελεσμένη πώληση day-ahead | MWh |
| ΔQ_ID,k,t | Καθαρή εκτελεσμένη διόρθωση στη συναλλαγή k | MWh |
| P_ch,t / P_dis,t | Ισχύς φόρτισης / εκφόρτισης | MW |
| E_t | Αποθηκευμένη ενέργεια στην αρχή περιόδου | MWh |
| I_t | Καθαρή έγχυση στο σημείο σύνδεσης | MWh |
| δ_t | Απόκλιση έγχυσης από τη συνολική θέση | MWh |

Θετική Q σημαίνει πώληση, αρνητική Q αγορά. Οι εντολές που δεν εκτελέστηκαν δεν μεταβάλλουν τη θέση.

## Μπαταρία

E_(t+1) = E_t + η_ch P_ch,t Δt - P_dis,t Δt / η_dis

E_min <= E_t <= E_max

0 <= P_ch,t <= P_ch,max

0 <= P_dis,t <= P_dis,max

Όπου χρειάζεται αποκλεισμός ταυτόχρονης λειτουργίας, χρησιμοποιούμε u_t ∈ {0, 1}:

P_ch,t <= u_t P_ch,max

P_dis,t <= (1 - u_t) P_dis,max

Δεν θεωρούμε ότι οι τιμές ή οι απώλειες αρκούν πάντα για να αποτρέψουν ταυτόχρονη φόρτιση και εκφόρτιση. Η αρχική ενέργεια είναι δεδομένη. Η τελική ενέργεια περιορίζεται ή αποτιμάται με προκαθορισμένο κανόνα, ίδιο για τις συγκρινόμενες στρατηγικές.

## Έγχυση και θέση

I_t = G_t - C_t + (P_dis,t - P_ch,t) Δt

Q_t = Q_DA,t + Σ_k ΔQ_ID,k,t

δ_t = I_t - Q_t

Ορίζονται όρια καθαρής εισαγωγής και εξαγωγής στο σημείο σύνδεσης. Το αν επιτρέπεται φόρτιση από το δίκτυο, περικοπή ή εξαγωγή της μπαταρίας είναι ρητή παράμετρος του case study.

## Οικονομικό αποτέλεσμα

Π = Σ_t [p_DA,t Q_DA,t + Σ_k p_ID,k,t ΔQ_ID,k,t
         + S_t(δ_t) - fees_t - degradation_t]

Το S_t είναι υπογεγραμμένη ταμειακή ροή εκκαθάρισης. Ο ακριβής κανόνας θα οριστεί από τους εφαρμοστέους κανόνες και τα δεδομένα. Δεν υποθέτουμε αυθαίρετα ότι surplus και deficit έχουν την ίδια τιμή ή ότι οι τιμές ενεργοποίησης εξισορρόπησης είναι τιμές εκκαθάρισης αποκλίσεων.

Η ενέργεια της μπαταρίας δεν δημιουργεί δεύτερο ξεχωριστό έσοδο αν έχει ήδη περιληφθεί στις εκτελεσμένες συναλλαγές και στην απόκλιση. Spread/slippage ενσωματωμένα σε fill price δεν αφαιρούνται ξανά.

Η αρχική προσέγγιση degradation θα είναι κόστος ανά MWh throughput με σαφή βάση μέτρησης και sensitivity analysis. Δεν ισοδυναμεί με πλήρες ηλεκτροχημικό μοντέλο.

## Απόφαση έναντι εκκαθάρισης

Πριν από το κλείσιμο μιας δημοπρασίας, η τιμή εκκαθάρισής της είναι άγνωστη. Απαιτείται πρόβλεψη ή σενάρια. Μετά τη δημοσίευση τιμής μπορεί να χρησιμοποιηθεί η τιμή μόνο σε αποφάσεις που παραμένουν επιτρεπτές· η κλεισμένη θέση δεν αλλάζει αναδρομικά.

Η φυσική εκτέλεση αντιμετωπίζει τις πραγματοποιημένες συνθήκες. Αν μια εντολή γίνει ανέφικτη λόγω νέας διαθεσιμότητας, καταγράφεται η πραγματική εφικτή ενέργεια και η απόκλιση, όχι σιωπηρή διόρθωση του ιστορικού προγράμματος.

## Σενάρια και CVaR

Για σενάρια s με βάρη w_s >= 0 και Σ_s w_s = 1:

maximize Σ_s w_s Π_s - λ CVaR_α(L)

L_s = -Π_s

CVaR_α(L) = z + (1 / (1 - α)) Σ_s w_s ξ_s

ξ_s >= L_s - z, ξ_s >= 0, 0 < α < 1, λ >= 0.

Οι αποφάσεις πριν από την αποκάλυψη πληροφορίας είναι κοινές στα σενάρια. Μελλοντικές αποφάσεις διαφοροποιούνται μόνο όταν η πληροφορία που δικαιολογεί τη διαφοροποίηση έχει γίνει διαθέσιμη. Αυτοί είναι οι περιορισμοί μη προεξόφλησης του μέλλοντος.

Η πρώτη επέκταση θα χρησιμοποιεί περιορισμένο σύνολο σεναρίων και κυλιόμενο ορίζοντα. Εκτελείται μόνο η άμεση επιτρεπτή απόφαση. Οι συσχετίσεις μεταξύ περιόδων, παραγωγής και τιμών διατηρούνται όπου μπορούν να εκτιμηθούν.

## SciPy και έλεγχος λύσης

Το formulation.py θα δημιουργεί διανύσματα, sparse πίνακες, bounds, integrality και χάρτη ονομάτων προς indices. Το solver.py θα χρησιμοποιεί linprog ή milp και θα επιστρέφει status, objective, χρόνο, gap και διαθέσιμη λύση.

Το validation.py θα επανυπολογίζει ανεξάρτητα φυσικά ισοζύγια, περιορισμούς και objective. Time limit με εφικτή λύση δεν αναφέρεται ως απόδειξη βέλτιστου. Άγνωστο ή μη εφικτό status δεν οδηγεί σε εντολή.

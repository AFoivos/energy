# Αρχιτεκτονική

## Αρχές

Η επιχειρησιακή λογική βρίσκεται στο src/aegean. Τα notebooks, το CLI και το Streamlit καλούν την ίδια λογική. Δεν εισάγεται πρόσβαση σε μελλοντικά actuals μέσα στις πολιτικές ή στον optimizer.

Όλα τα Python αρχεία είναι προς το παρόν κενά. Οι παρακάτω διεπαφές είναι απαιτήσεις σχεδιασμού.

## Διαδρομή δεδομένων

XLSX → ανάγνωση → επικύρωση → κανονικοποίηση → χρονικά επιτρεπτό snapshot → πρόβλεψη → πολιτική → risk checks → προσομοιωμένα fills → φυσική παράδοση → εκκαθάριση → report.

Ο engine διατηρεί ξεχωριστά το ιστορικό πραγματικών εκβάσεων και την πληροφορία που επιτρέπεται να δει η πολιτική.

## Ευθύνες modules

| Module | Ευθύνη | Δεν αναλαμβάνει |
| --- | --- | --- |
| config | Ρυθμίσεις και έλεγχος παραμέτρων | Καθολικό mutable state |
| data | Ανάγνωση, provenance, σχήμα και ποιότητα | Πρόβλεψη ή εκτέλεση |
| forecasting | Features, fit/predict, σενάρια και αξιολόγηση | Πρόσβαση σε future actuals |
| optimization | Φυσικό μοντέλο, LP/MILP και έλεγχος λύσης | Ανάγνωση Excel ή αλλαγή πραγματικών θέσεων |
| trading | Θέσεις, πολιτικές, risk checks και fills | Λογιστική εκκαθάριση της ίδιας συναλλαγής δεύτερη φορά |
| backtesting | Χρονική αναπαραγωγή, delivery, settlement και μετρικές | Tuning σε τελικό holdout |
| reporting | Γραφήματα και εξαγωγή | Επανυπολογισμό στρατηγικής με διαφορετική λογική |
| app / cli | Είσοδος χρήστη και orchestration | Ανεξάρτητη υλοποίηση μοντέλων |

## Αντικείμενα που θα οριστούν

Configuration, validated dataset, information snapshot, forecast, scenario set, portfolio state, action proposal, risk decision, order, fill, physical delivery, settlement record και run result.

Οι ποσότητες θα έχουν σαφή μονάδα. Order, fill και physical delivery είναι διαφορετικά γεγονότα. Το αναγνωριστικό γεγονότος χρησιμοποιείται για αποφυγή διπλής επεξεργασίας.

## Χρονικός βρόχος

1. Δημοσίευση νέας επιτρεπτής πληροφορίας.
2. Ενημέρωση κατάστασης και προηγούμενων fills.
3. Κατασκευή snapshot σύμφωνα με available_at.
4. Πρόταση πολιτικής.
5. Έλεγχος φυσικών, χρονικών και χρηματοοικονομικών ορίων.
6. Προσομοίωση εκτέλεσης.
7. Παράδοση όταν φτάσει η αντίστοιχη περίοδος.
8. Εκκαθάριση όταν δημοσιευτεί ο αντίστοιχος κανόνας/τιμή.
9. Καταγραφή συμβάντων.

Η οριστική εκκαθάριση μπορεί να είναι μεταγενέστερη της παράδοσης. Προσωρινή αποτίμηση και τελικό settlement παραμένουν ξεχωριστά.

## SciPy

Ο optimizer απομονώνει διατύπωση, επίλυση και έλεγχο. Ο πίνακας indices διατηρεί ονόματα μεταβλητών και περιορισμών για διάγνωση. Η επαλήθευση δεν βασίζεται μόνο στο success flag του solver.

## Αρχεία και εξαρτήσεις

Raw XLSX παραμένουν αμετάβλητα. Επεξεργασία σε pandas/NumPy στη μνήμη και προαιρετική εξαγωγή XLSX. Δεν απαιτείται SQL ή cloud.

Τα dependency ranges του pyproject.toml δεν είναι lockfile. Η εγκατάσταση και η πλήρης συμβατότητα δεν έχουν δοκιμαστεί. Πριν αναφερθεί reproducible run χρειάζονται ακριβείς εκδόσεις, δεδομένα και configuration.
